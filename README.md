# 모일까

프로젝트마다 따로 일정을 모으는 페이지예요. 관리자가 프로젝트(예: "A 프로젝트 킥오프", "B 프로젝트 회의")를 만들어 링크를 보내면, 받은 사람들이 닉네임으로 들어와 장소마다 갈 수 있는 시간과 안 되는 시간(빨강)을 드래그로 칠해요. 같은 칸을 칠한 사람이 많을수록 색이 진해져요.

- 프로젝트 만들기·지우기·전체 목록 보기는 **관리자만** 할 수 있어요. Google 로그인과 Firestore 규칙으로 막아요.
- 참여자는 로그인 없이 **프로젝트 링크**(`…/Moilkka/?p=프로젝트ID`)로 들어와요. 프로젝트 ID는 무작위 12자라서, 링크를 받지 않은 프로젝트에는 들어갈 수 없어요.
- 프로젝트마다 기간(최대 1년), 최대 인원(2~12명), **장소 후보**(최대 4곳, 예: 서울·대전·기타)를 정해요.
- 하루 통째로 안 되는 날은 **종일 불가** 도구를 고른 뒤 달력의 날짜를 누르면 ✕로 표시돼요. 다시 누르면 풀려요. 시간표에서 옆으로 드래그해 여러 날을 한 번에 표시할 수도 있어요. 내가 표시한 ✕를 전부 없애려면 도구 아래의 **✕ 모두 풀기**를 누르세요.
- 달력의 날짜마다 그날 장소별로 올 수 있는 사람 수(`2·3·0`, 장소 하나만 볼 땐 `○3`)와 종일 불가인 사람 수(`✕1`)가 나와요.
- 시간표 위 **모두 | 내 표시**에서 **내 표시**를 누르면 내가 칠한 것만 보이고, 왼쪽에 날짜별로 "서울 10–14시 · 서울·대전 14–16시 · 불가 18–20시"처럼 정리돼요.
- 관리자는 **일정**(예: 연습)을 잡을 수 있어요. 날짜·시간·장소와 함께 제목, **참가자**, 예약 링크, 장소 사진, 메모를 붙이면 프로젝트 맨 위에 모두에게 보여요. 전체가 모이는 일정도, 몇 명만 모이는 일정도 잡을 수 있고, **사람별**로 누가 어떤 일정에 참가하는지 볼 수 있어요.

### 장소별로 되는 시간은 이렇게 칠해요

시간표는 한 장이고, **장소가 붓**이에요. 칠하기 전에 그 시간에 갈 수 있는 곳을 붓으로 고르세요.

| 붓 | 뜻 |
| --- | --- |
| **서울 / 대전 / 기타** | 그 장소엔 갈 수 있어요. 한 칸에 여러 장소를 겹쳐 칠할 수 있어요 (서울 붓으로 칠한 칸에 대전 붓을 또 칠하면 "서울·대전"). 이미 그 장소가 칠해진 칸에서 드래그를 시작하면 그 장소만 빠져요. |
| **어디든** | 모든 장소 다 돼요. |
| **불가** | 어디서도 안 돼요. |
| **종일 불가 / 지우기 / 보기** | 전과 같아요. 처음 들어오면 붓이 안 골라진 **보기** 상태예요. |

시간표 위 **보기** 칸에서 어떻게 볼지 골라요.

- **비교**(기본): 칸 색은 그 시간에 가장 많이 올 수 있는 장소예요. 모든 장소가 같으면 초록이에요. 주 보기 칸의 `2·3·0`은 서울·대전·기타 순서로 올 수 있는 사람 수예요.
- **서울 / 대전 / 기타**: 그 장소에 올 수 있는 사람(초록)과 못 오는 사람(빨강)만 봐요.

**추천 시간**은 시간마다 가장 많이 올 수 있는 장소를 골라 "대전 3/3명 · 서울 2 · 기타 2"처럼 보여 줘요. 대전에 더 많이 모이면 대전에서, 아니면 서울에서 모이는 식으로 고르면 돼요.

장소 후보가 생기기 전에 만든 프로젝트는 `서울, 대전, 기타`로 열리고, 예전 방식으로 칠한 기록은 자동으로 바뀌어요.
- 예전 기본(서울)에 칠한 시간 → 서울
- "서울과 같음" → 그 장소도 됨
- 따로 칠한 장소 → 그 장소 (단, 서울 일정을 복사만 하고 고치지 않은 장소는 칠하지 않은 것으로 봐요)
- "못 감" → 그 장소는 안 됨

관리자는 프로젝트 화면의 **장소 후보 고치기**에서 장소마다 칸 하나씩 이름을 바꾸거나, 칸을 비워 그 장소를 뺄 수 있어요. 이름을 바꿔도 칠한 기록과 그 장소 일정은 그대로 따라가요.

## 파일 구성

| 파일 | 역할 |
| --- | --- |
| `index.html` | 화면 뼈대(HTML)만 있어요 |
| `css/style.css` | 모양 전부 |
| `js/main.js` | 시작점: `?p=` 없으면 프로젝트 목록, 있으면 그 프로젝트 화면을 불러와요 |
| `js/util.js`, `js/holidays.js` | 날짜·글자 도우미, 공휴일 표 |
| `js/db.js` | Firebase 연결 (설정이 비어 있으면 이 브라우저에만 저장하는 "혼자 써보기") |
| `js/projects.js` | 프로젝트 문서 읽기, 장소 후보 다듬기, 최근 연 프로젝트 |
| `js/home.js` | 프로젝트 목록·만들기·지우기 (관리자 로그인) |
| `js/board/state.js` | 프로젝트 화면의 상태와 계산 (누가 언제 어느 장소로 올 수 있는지, 예전 기록 바꾸기) |
| `js/board/view.js` | 달력·시간표·내 표시·참여자·추천 시간 그리기 |
| `js/board/paint.js` | 장소 붓으로 칠하기, 종일 불가, 저장 |
| `js/board/places.js` | 보기(비교·장소별) 칸, 장소 후보 고치기 |
| `js/board/meets.js` | 일정 카드·사람별 보기·일정 잡기 창(참가자 고르기)·사진 줄이기 |
| `js/board/index.js` | 프로젝트 화면 시작, 참여자/일정 실시간 받기, 클릭 처리 |
| `config.js` | Firebase 연결 설정 (여기만 고치면 돼요) |
| `firestore.rules` | Firestore 보안 규칙 (Firebase 콘솔에 붙여넣기용) |

빌드 과정은 없어요. 브라우저가 `js/` 파일을 그대로 불러와요. 대신 파일을 더블클릭해서(`file://`) 열면 동작하지 않아요. 내 컴퓨터에서 보려면 이 폴더에서 `python3 -m http.server`를 실행하고 `http://localhost:8000`을 여세요.

## 1. GitHub Pages에 올리기

1. GitHub에서 새 저장소를 만들어요. 예: `Moilkka` (Public)
2. 저장소 화면에서 **Add file → Upload files**를 누르고 이 폴더의 파일과 `css`, `js` 폴더를 모두 끌어다 놓은 뒤 **Commit changes**를 눌러요.
3. **Settings → Pages**로 가서 Source를 **Deploy from a branch**, Branch를 **main / (root)** 로 고르고 **Save**를 눌러요.
4. 1~2분 뒤 `https://<내 아이디>.github.io/<저장소 이름>/` 에서 열려요. 주소는 저장소 이름의 대소문자를 그대로 따라요.

이 상태로는 **혼자 써보기 모드**예요. 이 브라우저에만 저장되고, 이 브라우저가 곧 관리자라서 바로 프로젝트를 만들어 볼 수 있어요. 같이 쓰려면 2단계를 이어서 하세요.

## 2. Firebase 연결하기 (무료)

1. https://console.firebase.google.com 에서 **프로젝트 추가**를 눌러 프로젝트를 만들어요. Google 애널리틱스는 꺼도 돼요.
2. 왼쪽 메뉴 **Firestore Database → 데이터베이스 만들기**를 눌러요.
   - 위치는 `asia-northeast3 (서울)`을 고르세요.
   - **프로덕션 모드**로 시작해요.
3. Firestore 화면의 **규칙** 탭에서 기존 내용을 지우고 `firestore.rules` 내용을 붙여넣은 뒤 **게시**를 눌러요. (Realtime Database가 아니라 **Firestore Database**의 규칙 탭이에요.)
4. 왼쪽 메뉴 **Authentication → 시작하기**를 누르고, **로그인 방법** 탭에서 **Google**을 사용 설정해요.
5. 같은 화면의 **설정 → 승인된 도메인**에 `<내 아이디>.github.io` 를 추가해요. (주소 뒤의 `/Moilkka/`는 빼고 도메인만)
6. 프로젝트 개요 옆 **톱니바퀴 → 프로젝트 설정 → 일반 → 내 앱**에서 웹 아이콘 `</>`을 눌러 웹 앱을 등록해요. Firebase Hosting은 체크하지 않아도 돼요.
7. 화면에 나오는 `firebaseConfig`의 값(apiKey, authDomain, projectId …)을 `config.js`에 붙여넣어요.
8. GitHub 저장소에서 `config.js`를 열고 연필 아이콘으로 수정하거나 새 파일을 다시 올린 뒤 커밋해요.

1~2분 뒤 페이지를 새로고침하면 상단의 "혼자 써보기 모드" 안내가 사라져요.

**페이지를 새 버전으로 올릴 때 `firestore.rules`도 바뀌었다면**, 먼저 3번처럼 규칙을 다시 게시한 다음 파일을 올리세요. 새 규칙은 예전 페이지도 그대로 받아 주지만, 예전 규칙은 새 기능(장소, 일정의 제목·참가자 등)의 저장을 거부해요.

## 3. 나를 관리자로 지정하기 (한 번만)

1. 첫 화면(`?p=` 없는 주소) 오른쪽 위의 **관리자 로그인**을 눌러 Google 계정으로 로그인해요.
2. "이 계정은 아직 관리자가 아니에요"라는 안내와 함께 UID가 나와요. **복사**를 눌러요.
3. Firebase 콘솔 → **Firestore Database → 데이터** → **컬렉션 시작**을 눌러요.
   - 컬렉션 ID: `admins`
   - 문서 ID: 방금 복사한 UID (자동 ID 버튼은 누르지 마세요)
   - 필드: 아무거나 하나 (예: `memo` / string / `관리자`)
4. 페이지를 새로고침하면 왼쪽에 **새 프로젝트** 양식이 나와요.

관리자를 더 두려면 그 사람도 같은 방법으로 로그인해 UID를 받고, `admins`에 문서를 하나 더 만들면 돼요. 관리자 명단은 Firestore에만 있고 GitHub 저장소에는 올라가지 않아요.

## 4. 프로젝트 만들고 보내기

1. 첫 화면에서 이름, 시작일·종료일, 최대 인원, 장소 후보를 정하고 **만들기**를 눌러요. 장소 후보는 쉼표로 나눠 적고, 첫 번째가 기본 장소예요.
2. 오른쪽 목록에서 **링크 복사**를 눌러 그 프로젝트 참여자에게 보내요.
3. 다 쓴 프로젝트는 **지우기**를 누르면 참여자 기록과 일정까지 모두 지워져요.

참여자가 `?p=` 없는 첫 화면에 들어오면 프로젝트 목록 대신 "최근 연 프로젝트"(그 브라우저에서 열어 본 것)만 보여요.

## 5. 일정 잡기 (관리자)

첫 화면에서 관리자로 로그인한 브라우저로 프로젝트 링크를 열면, 이름 옆에 **관리자** 표시가 붙고 일정 칸이 나와요.

1. **추천 시간** 옆의 **+ 일정**을 누르면 그 날짜·시간·장소가 채워지고, 그 시간·장소에 올 수 있는 사람들이 참가자로 미리 골라져 창이 열려요. 직접 잡으려면 일정 칸의 **+ 일정 잡기**를 누르세요(처음엔 전체가 골라져 있어요).
2. **제목**(예: 전체 합주, 보컬 파트 연습)을 적고 **참가자**를 눌러 넣고 빼요. 이름 옆에 그 날짜·시간·장소에 그 사람이 칠한 표시(가능·일부·불가)가 나와서 고르기 쉬워요. 날짜나 시간, 장소를 바꾸면 표시도 따라 바뀌어요.
3. 장소 이름, 예약 링크(네이버 지도·스페이스클라우드 등), 장소 사진, 메모를 넣고 **저장**해요.
4. 일정은 프로젝트 맨 위 카드로 모두에게 바로 보이고, 달력과 시간표에 파란 점·막대로 표시돼요. 내가 참가하는 일정엔 **나도 참가**가 붙어요. 카드의 날짜를 누르면 그날 시간표로 가요.
5. 일정 칸의 **사람별**을 누르면 사람마다 참가하는 일정이 한 줄로 모여요. 자리를 비운 사람도 참가자로 넣어 둔 일정이 있으면 "자리 비움"으로 남아요.

사진은 Firestore 문서 안에 들어가요(무료 요금제에선 Firebase 사진 저장소를 쓸 수 없어서). 고른 사진은 자동으로 줄여서 400 KB 안팎으로 저장해요.

## 알아둘 점

- **참여자는 로그인이 없어요.** 프로젝트 링크를 아는 사람은 누구나 그 프로젝트에서 칠하고 자리를 비울 수 있어요. 링크는 참여자끼리만 공유하세요. 일정은 관리자만 잡고 고칠 수 있어요.
- **같은 닉네임 = 같은 사람이에요** (프로젝트마다 따로). 다른 기기에서도 같은 닉네임으로 들어오면 내가 칠한 기록이 이어져요. 영문 대소문자는 구분하지 않아요.
- **카카오톡 같은 앱 안 브라우저에서는 Google 로그인이 막혀 있어요.** 관리자 로그인은 Chrome이나 Safari에서 하세요. 참여자는 로그인하지 않으니 카톡으로 링크를 열어도 괜찮아요.
- **Firebase 무료(Spark) 한도**는 저장 1 GiB, 하루 읽기 5만 회·쓰기 2만 회예요. 모든 프로젝트가 이 한도를 함께 써요.
  - 저장 공간은 넉넉해요. 한 사람이 4개월을 꽉 채워 칠해도 인덱스까지 50 KB 안팎이라, 6명짜리 프로젝트 하나가 수백 KB예요. 사진을 붙인 일정은 하나에 400 KB 안팎이에요.
  - 하루 사용량은 드래그 한 번마다 쓰기 1회, 그리고 그 프로젝트를 열어 둔 사람 수만큼 읽기가 생겨요. 6명이 동시에 열어 두고 칠해도 하루 8천 번쯤 드래그해야 한도에 닿아요.
  - 한도를 넘어도 요금은 나오지 않아요. 그날만 저장이 멈추고 태평양 시간 자정(한국 시간 오후 4~5시)에 다시 풀려요.
- **공휴일 표시**는 2026~2027년만 들어 있어요. 더 필요하면 `js/holidays.js`에 추가하세요.
