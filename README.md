# 모일까

프로젝트마다 따로 일정을 모으는 페이지예요. 관리자가 프로젝트(예: "A 프로젝트 킥오프", "B 프로젝트 회의")를 만들어 링크를 보내면, 받은 사람들이 닉네임으로 들어와 선호 시간(초록)과 안 되는 시간(빨강)을 드래그로 칠해요. 같은 칸을 칠한 사람이 많을수록 색이 진해져요.

- 프로젝트 만들기·지우기·전체 목록 보기는 **관리자만** 할 수 있어요. Google 로그인과 Firestore 규칙으로 막아요.
- 참여자는 로그인 없이 **프로젝트 링크**(`…/moilkka/?p=프로젝트ID`)로 들어와요. 프로젝트 ID는 무작위 12자라서, 링크를 받지 않은 프로젝트에는 들어갈 수 없어요.
- 프로젝트마다 기간(최대 1년)과 최대 인원(2~12명)을 정해요.
- 하루 통째로 안 되는 날은 **종일 불가** 도구를 고른 뒤 달력의 날짜를 누르면 ✕로 표시돼요. 다시 누르면 풀려요. 시간표에서 옆으로 드래그해 여러 날을 한 번에 표시할 수도 있어요. 내가 표시한 ✕를 전부 없애려면 도구 아래의 **✕ 모두 풀기**를 누르세요.
- 달력의 날짜마다 `○3 ✕1`처럼 그날 선호 시간이 있는 사람 수(○)와 종일 불가인 사람 수(✕)가 나와요.

파일 구성

| 파일 | 역할 |
| --- | --- |
| `index.html` | 페이지 전체 (HTML·CSS·JS 한 파일). `?p=` 없이 열면 프로젝트 목록, `?p=…`로 열면 그 프로젝트의 시간표 |
| `config.js` | Firebase 연결 설정 (여기만 고치면 돼요) |
| `firestore.rules` | Firestore 보안 규칙 (Firebase 콘솔에 붙여넣기용) |

---

## 1. GitHub Pages에 올리기

1. GitHub에서 새 저장소를 만들어요. 예: `moilkka` (Public)
2. 저장소 화면에서 **Add file → Upload files**를 누르고 이 폴더의 파일을 모두 끌어다 놓은 뒤 **Commit changes**를 눌러요.
3. **Settings → Pages**로 가서 Source를 **Deploy from a branch**, Branch를 **main / (root)** 로 고르고 **Save**를 눌러요.
4. 1~2분 뒤 `https://<내 아이디>.github.io/moilkka/` 에서 열려요.

이 상태로는 **혼자 써보기 모드**예요. 이 브라우저에만 저장되고, 이 브라우저가 곧 관리자라서 바로 프로젝트를 만들어 볼 수 있어요. 같이 쓰려면 2단계를 이어서 하세요.

## 2. Firebase 연결하기 (무료)

1. https://console.firebase.google.com 에서 **프로젝트 추가**를 눌러 프로젝트를 만들어요. Google 애널리틱스는 꺼도 돼요.
2. 왼쪽 메뉴 **Firestore Database → 데이터베이스 만들기**를 눌러요.
   - 위치는 `asia-northeast3 (서울)`을 고르세요.
   - **프로덕션 모드**로 시작해요.
3. Firestore 화면의 **규칙** 탭에서 기존 내용을 지우고 `firestore.rules` 내용을 붙여넣은 뒤 **게시**를 눌러요.
4. 왼쪽 메뉴 **Authentication → 시작하기**를 누르고, **로그인 방법** 탭에서 **Google**을 사용 설정해요.
5. 같은 화면의 **설정 → 승인된 도메인**에 `<내 아이디>.github.io` 를 추가해요. (주소 뒤의 `/moilkka/`는 빼고 도메인만)
6. 프로젝트 개요 옆 **톱니바퀴 → 프로젝트 설정 → 일반 → 내 앱**에서 웹 아이콘 `</>`을 눌러 웹 앱을 등록해요. Firebase Hosting은 체크하지 않아도 돼요.
7. 화면에 나오는 `firebaseConfig`의 값(apiKey, authDomain, projectId …)을 `config.js`에 붙여넣어요.
8. GitHub 저장소에서 `config.js`를 열고 연필 아이콘으로 수정하거나 새 파일을 다시 올린 뒤 커밋해요.

1~2분 뒤 페이지를 새로고침하면 상단의 "혼자 써보기 모드" 안내가 사라져요.

## 3. 나를 관리자로 지정하기 (한 번만)

1. 첫 화면(`?p=` 없는 주소) 오른쪽 위의 **관리자 로그인**을 눌러 Google 계정으로 로그인해요.
2. "이 계정은 아직 관리자가 아니에요"라는 안내와 함께 UID가 나와요. **복사**를 눌러요.
3. Firebase 콘솔 → **Firestore Database → 데이터** → **컬렉션 시작**을 눌러요.
   - 컬렉션 ID: `admins`
   - 문서 ID: 방금 복사한 UID
   - 필드: 아무거나 하나 (예: `memo` / string / `관리자`)
4. 페이지를 새로고침하면 왼쪽에 **새 프로젝트** 양식이 나와요.

관리자를 더 두려면 그 사람도 같은 방법으로 로그인해 UID를 받고, `admins`에 문서를 하나 더 만들면 돼요. 관리자 명단은 Firestore에만 있고 GitHub 저장소에는 올라가지 않아요.

## 4. 프로젝트 만들고 보내기

1. 첫 화면에서 이름, 시작일·종료일, 최대 인원을 정하고 **만들기**를 눌러요.
2. 오른쪽 목록에서 **링크 복사**를 눌러 그 프로젝트 참여자에게 보내요.
3. 다 쓴 프로젝트는 **지우기**를 누르면 참여자 기록까지 모두 지워져요.

참여자가 `?p=` 없는 첫 화면에 들어오면 프로젝트 목록 대신 "최근 연 프로젝트"(그 브라우저에서 열어 본 것)만 보여요.

## 알아둘 점

- **참여자는 로그인이 없어요.** 프로젝트 링크를 아는 사람은 누구나 그 프로젝트에서 칠하고 자리를 비울 수 있어요. 링크는 참여자끼리만 공유하세요.
- **같은 닉네임 = 같은 사람이에요** (프로젝트마다 따로). 다른 기기에서도 같은 닉네임으로 들어오면 내가 칠한 기록이 이어져요. 영문 대소문자는 구분하지 않아요.
- **카카오톡 같은 앱 안 브라우저에서는 Google 로그인이 막혀 있어요.** 관리자 로그인은 Chrome이나 Safari에서 하세요. 참여자는 로그인하지 않으니 카톡으로 링크를 열어도 괜찮아요.
- **Firebase 무료(Spark) 한도**는 저장 1 GiB, 하루 읽기 5만 회·쓰기 2만 회예요. 모든 프로젝트가 이 한도를 함께 써요.
  - 저장 공간은 넉넉해요. 한 사람이 4개월을 꽉 채워 칠해도 인덱스까지 50 KB 안팎이라, 6명짜리 프로젝트 하나가 수백 KB예요.
  - 하루 사용량은 드래그 한 번마다 쓰기 1회, 그리고 그 프로젝트를 열어 둔 사람 수만큼 읽기가 생겨요. 6명이 동시에 열어 두고 칠해도 하루 8천 번쯤 드래그해야 한도에 닿아요.
  - 한도를 넘어도 요금은 나오지 않아요. 그날만 저장이 멈추고 태평양 시간 자정(한국 시간 오후 4~5시)에 다시 풀려요.
- **공휴일 표시**는 2026~2027년만 들어 있어요. 더 필요하면 `index.html` 스크립트 맨 위의 `HOLI`에 추가하세요.
